# Object Jobs

Garage exposes object operations rather than a native directory abstraction.
Garage UI implements folders as S3 key prefixes and expands each selected
prefix into concrete object operations in a durable backend job.

## Behavior

- Explicit object keys and recursive prefixes can be mixed in one request.
- Duplicate objects and objects already covered by a selected prefix are
  processed once.
- Copy and move preserve the selected folder name below `destinationPrefix`.
  Copying `photos/2026/` to `archive/` produces
  `archive/2026/<relative-key>`.
- Explicit objects are placed directly below `destinationPrefix` using their
  base name.
- A same-bucket folder cannot target itself or one of its descendants.
- `skip` leaves an existing destination untouched and counts it as skipped.
  `overwrite` replaces it.
- Move uses Garage's server-side copy followed by source deletion. A restarted
  job recognizes a destination that was copied before the source was deleted.
- Cancellation is cooperative. Requests already executing may finish before
  the job reaches `cancelled`.
- The embedded bbolt database stores job aggregates, concrete work items, and
  failures. Non-terminal jobs are requeued on backend startup.

## Create A Job

`POST /api/v1/object-jobs`

Use an `Idempotency-Key` header when retrying a create request. Keys are scoped
to the authenticated user and retained for the lifetime of the job record.

```json
{
  "operation": "copy",
  "sourceBucket": "pics",
  "objects": ["cover.jpg"],
  "prefixes": ["albums/2026/"],
  "destinationBucket": "archive",
  "destinationPrefix": "imports/",
  "conflictPolicy": "skip"
}
```

The endpoint returns `202 Accepted` and an `ObjectJob` in the standard API
response envelope.

For delete jobs, omit all destination fields:

```json
{
  "operation": "delete",
  "sourceBucket": "pics",
  "objects": ["old.jpg"],
  "prefixes": ["temporary/"]
}
```

## Progress And Lifecycle

`GET /api/v1/object-jobs/{id}` returns current aggregate progress.

Statuses:

| Status | Meaning |
| --- | --- |
| `queued` | Waiting for an active-job worker |
| `scanning` | Resolving prefixes and object metadata |
| `running` | Executing concrete object operations |
| `cancelling` | Cancellation requested |
| `completed` | Every object succeeded or was skipped |
| `completed_with_errors` | At least one concrete object failed |
| `failed` | The job could not scan or initialize |
| `cancelled` | Cooperative cancellation finished |

`progress` is zero while discovery is incomplete. During execution it is
`processed / discovered * 100`. Byte counters are informational and do not
replace object counts, because S3 copy completion is reported per object.

Other endpoints:

- `GET /api/v1/object-jobs?limit=20` lists recent jobs.
- `GET /api/v1/object-jobs/{id}/failures?offset=0&limit=50` lists concrete
  failures with source key, destination key, and error.
- `POST /api/v1/object-jobs/{id}/cancel` requests cancellation.

Users can access only their own jobs. Administrators can inspect all jobs.

## Authorization

Create authorization is evaluated dynamically from the requested operation:

| Operation | Source permissions | Destination permissions |
| --- | --- | --- |
| Copy | `object.list`, `object.read` | `object.read`, `object.write` |
| Move | `object.list`, `object.read`, `object.delete` | `object.read`, `object.write` |
| Delete | `object.list`, `object.delete` | None |

Bucket-prefix access-control bindings are evaluated for the source and
destination buckets when the job is created. Persisted jobs are not
re-authorized per object when they resume.

## Configuration

```yaml
object_jobs:
  enabled: true
  database_path: /var/cache/garage-ui/jobs.db
  concurrency: 4
  max_active: 1
  retention: 72h
```

`concurrency` bounds S3 requests within each job. `max_active` bounds the number
of jobs running at once. Their product is the maximum object-operation
concurrency generated by this service instance.

The database is local to one backend instance. Run a single API replica unless
the job runner and store are replaced with a shared coordination system.
